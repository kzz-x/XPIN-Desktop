# macOS 视觉基准｜截图驱动设计

**状态：用户视觉参考截图已提供并归档于 references/macos/；风格卡已建立 (docs/MACOS-STYLE-CARD.md)。更新：2026-10-16。**

## 已确定的输入方式

首期视觉基准来自**用户提供的现有 macOS 风格视觉模板截图**（共 4 张核心截图：浏览器卡片、章节弧形盘、金句气泡与 3D 图标、影视化桌面全组件还原）。根据截图分析和重建成原生可编辑的代码 UI 组件。

- 只需要**截图作为视觉参考**，不要求上传或解析 AE 工程、表达式、关键帧或预合成。
- 先把 **macOS Cinematic Skin** 做到画面和动效标准，再扩展 Windows、iOS、Android、Node Canvas、Custom UI。
- “按截图”指尊重其可见的设计语言、布局、元素关系和质感；截图无法提供的行为、动态曲线和镜头节奏由 Agent 主动设计，通过动态 Previs 审核。
- 不因参考图是 macOS 就把通用数据结构、行为或渲染器写成 macOS 专属。
- **已完整提炼字体名称（标小智无界黑、苹方UI-简）、色值（#F96257, #FDBC2C, #51A7F9, #2BC83D 等）、尺寸与质感规范。**

## 收到截图后的提取顺序

### 1. 视觉拆解（先做风格卡）

- 整体：画幅、镜头机位、留白、光照方向、背景、纵深、信息主次。
- 设计 Token：字体层级、字号、字重、文字对比、配色、明暗、圆角、边框、间距、投影、透光和模糊强度。
- 部件：Dock、窗口标题栏、工具栏、文件项、照片区域、滚动条、指针、弹窗、信息卡等。
- 状态：默认、聚焦、悬停、选中、按下、打开、最大化、缩放。
- 可见的影视化处理：夸张比例、素材区放大、窗口悬浮、阴影、局部特写等。
- **缺失项标待确认/待设计**，不要凭经验推断成“原模板就是如此”。

### 2. 组件化重建

把截图中的可复用视觉提取成 macOS Skin Tokens 与可用的 Component Variants：

- **Tokens**：颜色、类型、圆角、距离、阴影、材质、字体等。
- **Variants**：macOS 的窗口、Finder、Preview、Dock、Cursor、菜单/弹窗等。
- **Content / State**：照片、文本、文件列表、窗口焦点、缩放状态由通用数据模型持有。
- **Motion / Camera**：镜头与行为另层控制，保证画面换皮后仍能复用核心时间线。

优先用代码绘制可编辑 UI；可将用户提供的纹理、图标等合法资产作为补充。不要用整张参考截图作为不可编辑的“假窗口”交付。

### 3. 先静态风格验收，再动态验收

1. 选取截图中最有代表性的 **桌面全景、Finder 文件窗口、Preview 图片窗口、图片特写**（以实际收到的素材为准）。
2. 还原对应画面的关键帧 Styleframes，给出**参考图与渲染图的并列对比**：布局、字号、比例、边框、材质、阴影、景深、主体可读性。
3. 标出尚未对齐之处，集中迭代至认可的视觉质量。
4. 视觉基准确认后，再做“打开图片→定位→缩放→镜头特写”的**低成本动态 Previs**，审核指针、窗口反馈、缓动、景别、切镜与整体节奏。
5. 动态设计经认可，才把动作提炼为可复用的语义接口和组件预设。

**参考截图只决定视觉锚点，不替代动态验收。** 如果截图数量少，可以先建最小风格卡，逐步补全；无需预设必须收到固定数量图片。

## 后续换 Skin 的正确含义

更换视觉皮肤不是简单地替换背景或 CSS：

| 层级 | 跨 Skin 复用 | 需要针对系统适配 |
| --- | --- | --- |
| 素材/场景语义 | 图片、文字、文件、信息重点、稳定 ID | 路径/控件命名等视系统而定 |
| 高层动作 | 打开图片、放大目标、切换窗口、显示卡片 | 双击、轻触等操作映射 |
| 状态模型 | 文件选择、窗口焦点、缩放比例、区域锚点 | 系统独有状态 |
| 视觉 | 内容对象身份、可读性/安全区要求 | Token、字体、组件层级、图标、系统动效 |
| 导演 | 整体叙事、口播 Marker、镜头目标 | 因布局变化重新构图与局部节奏适配 |

**第一阶段验收只考 macOS 视觉。** 架构上预留 Skin 接口即可；Windows 等在 macOS 基准确认并跑通完整链路之后再实际制作和验收。
