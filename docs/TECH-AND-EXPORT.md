# 架构原则、Agent 接口与导出边界 V0.2

**更新：2026-10-16。性质：技术设计约束与候选路径，不是已验证的实现承诺。正式技术选型由 Codex 在可运行 Spike 后建议。**

## 当前视觉输入与换皮架构决策

- 首期视觉只接收**用户提供的 macOS 视觉模板截图**作为参考，不把 AE 工程解析、关键帧或 AE 脚本作为生产依赖。
- **先做 macOS Skin**，接口上保留 Windows/iOS/Android/节点卡片扩展。Skin 包括 Tokens、组件结构与行为适配，而非仅 CSS 换色。
- 同一份场景语义、内容对象、时间线和 Director 镜头目标应尽量跨 Skin 复用；因窗口尺寸或操作差异变化时，需要自动构图和独立的系统行为映射。
- 截图尚未提供；具体 Token、窗口度量和组件外观不能提前标成已实现。

## 核心目标

**素材 + 语义动作 + 界面组件 + 导演镜头 + 确定性时间线 → 可编辑 HTML / 视频 / 后期素材**。

系统应在本地优先运行、尽可能离线可用；Agent 能直接生成或编辑结构化场景，使用者能在浏览器中预览并修改，而不是只能通过重新生成整段视频来改图或改字。

## 推荐逻辑分层（不限制具体代码目录）

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| Assets / 素材 | 图片、文字、视频、字体与引用，ID、授权信息 | 行为逻辑 |
| Scene Data / 场景 | 内容树、组件身份、配置、关联关系、风格选择 | 浏览器动画实现 |
| Skin / 视觉 | macOS / Windows / Creative 外观 Tokens | 语义动作 |
| Components / 组件 | Window、Finder、Preview、Photos、Card 等状态与可视表示 | 摄影机决策 |
| Semantic Actions / 语义 | openPhoto、zoomToRegion 等抽象用户意图 | 固定屏幕像素坐标 |
| Performance / 表演 | 鼠标、窗口反馈、手势及可调节的操作节奏 | 业务素材定义 |
| Director / 镜头 | 机位、构图、焦点、切镜、镜头组接 | 修改 UI 内部业务状态 |
| Timeline / 时间线 | Marker、动作起止、轨道、帧级求值 | 直接依赖连续播放计时 |
| Renderer / 渲染 | 时间 T 的稳定画面、格式输出 | 动作语义解释 |
| Editor / 编辑器 | 预览、参数、资产、镜头/时间线编辑 | 持有唯一隐藏状态 |

### 必须解决的技术问题

1. **时间随机访问**：任意帧独立求值，截图和视频对同一帧应一致；操作系统式动画不能依赖之前已经“播放过”。
2. **稳定定位**：鼠标和相机寻找组件 ID / Anchor。图片某局部可指定归一化区域或语义 Region，而不是硬编码绝对坐标。
3. **真实可改**：图片、文字、皮肤与镜头参数可以在 HTML 工具内改；修改后能导出完整场景。
4. **场景可复现**：所有外部素材、字体、浏览器依赖和随机数种子都可定位或冻结；加载完成前不算有效渲染帧。
5. **可交付性**：开发使用模块化工程，交付支持打包独立 HTML。独立 HTML 可以嵌入素材或采用清楚的离线附件打包方式，不能只给一份依赖失效本地绝对路径的页面。
6. **渲染性能**：编辑实时预览应轻；高质量导出与三维效果按镜头需求选择，不强制所有 UI 用昂贵三维渲染。
7. **两类离线能力分别测试**：独立 HTML 本地打开，与借助 Chromium/Playwright/FFmpeg 导出视频是两项不同的能力，后者不能宣称零依赖。字体、图像加载、布局、帧率、逐帧一致性需要干净环境验证。
7. **AI 易操作**：清晰、稳定、有可读错误的场景格式；工具返回预览、验证结果和产物路径，避免让 Agent 反复猜 UI 状态。

## Agent 调用方式（概念接口，暂不锁语法）

希望支持下列用户层表达：

- “用 macOS 打开 photo.jpg，放大到芯片，5 秒时切微距，再转成节点卡片。”
- “同一内容改用 Windows Photos，画面 9:16，保留原有口播时点。”
- “只换图片和文案，不要改变已锁定镜头。”
- “输出可编辑 HTML 和可直接剪辑的视频。”

概念层操作可以包含：

| 意图 | 参数方向 |
| --- | --- |
| openPhoto | 素材 ID、系统、所用 App |
| zoomImageToRegion | 图片区域/目标元素、目标构图、持续时间 |
| focusWindow | 目标窗口、景别、背景弱化 |
| revealAnnotation | 文案、Anchor、入场方式 |
| morphToCard | 内容 ID、目的风格、过渡方式 |
| lockShot | 镜头 ID、锁定构图或时间等 |

**这些名字不是最终 API**。先建立能跑通单个镜头的场景模型，再决定采用 JSON、TS DSL、CLI 或组合方案。

## 可视化编辑

可采取“中间预览、左侧素材/组件、右侧属性、下方时间线”的基本布局。

编辑器要与 Agent 使用**同一场景数据模型**。不允许出现 Agent 编辑 JSON 后浏览器无法加载、或者可视化修改后不可回写的双轨状态。

首期“足够可用”的编辑能力为：替换照片 / 文字、切换 macOS / Windows、调节窗口/镜头基本参数、修改动作时间、逐帧播放与导出。高级曲线编辑可以后置。

## 导出与视频规格

### 短期优先

- 完整场景文件：可持续被 Agent 修改的源数据。
- 独立 HTML：本地浏览器打开可预览、替换素材、调整常用参数（具体打包规则需实验）。
- 视频：MP4（含合理色彩配置与可选音频），默认 1920×1080，支持 24/25/30/60fps 取决于渲染选项。
- 静帧与图像序列：用于视觉审核及宿主合成。
- 9:16 / 1:1 / 4K 等另行定义构图与质量策略，不能只裁剪原片。

### 中期按需求

- Alpha 通道画面、分层导出（例如前景/窗口/背景）与音效轨。
- 可导出镜头段落、Marker / shot metadata，方便 PR / AE 对接。

### 长期目标

- **PR / AE 面板**：管理 HTML 场景、预览、批量渲染替换、导入并更新宿主时间线素材。
- **原生可渲染桥接**：使 HTML/引擎场景尽量成为可按宿主时间请求帧的视频层；此路线需要真正的帧提供接口与缓存/浏览器进程方案，**不是把 HTML 面板 WebView 直接当作视频图层**。

## 后期集成注意

优先验证 **外部渲染器 + PR / AE 插件面板 + 自动更新素材** 这条可控链路。只要 Agent 修改场景后可重新生成并替换片段，已能显著减少手工导入/重做。

“在 PR 中不渲染 MP4 直接播放 HTML 并随序列导出”属于更远期、实现成本高的工作项。需要测试宿主 API、平台支持、缓存、透明度、音频、色彩空间与性能，不提前承诺。

## 可能参考的技术，不预设结论

- **Remotion**：逐帧渲染/React 动画的参考。
- **Motion Canvas**：场景节点、时间编排与程序化动效的参考。
- **Web Animations / GSAP 等**：运行时组件与交互表演，可评估是否适配确定性逐帧 seek。
- **Three.js / WebGL / CSS 3D**：2.5D 窗口舞台、少量景深/透视效果，按成本挑选。
- **FFmpeg / Chromium 自动化**：视频与图片序列导出的参考路线。

> 技术选型须先做一个“多镜头打开照片→缩放到局部→转换为卡片→任意帧跳转→独立 HTML→视频”闭环 Spike，实测后再收敛。

## 风险与验证

| 风险 | 应对 |
| --- | --- |
| WebView 面板不等于视频素材 | 先渲染后导入；原生帧桥接独立研究 |
| 各帧渲染时资源尚未加载 | 素材预加载/加载完成信号/失败提示 |
| 字体与系统 UI 因平台不一致 | 字体替代方案与许可核查；视觉回归图 |
| Skin 切换时组件布局失控 | 状态与视觉分层；关键系统写适配器 |
| 图片目标位置不一致 | Region + Anchor + 视觉预演校正 |
| 复杂运镜修改成本过高 | 默认轻镜头；构图锁；低成本 Previs |
| 浏览器视频输出颜色/Alpha 不可靠 | 样片与图像序列逐项测试 |
| 商标、图标、官方壁纸素材授权 | 区分用户自备资产、开放素材、原创替代资产 |

## 首期技术验收

**以 macOS 为唯一首轮画面质量标准**：收到用户视觉截图后完成风格卡、关键帧并排对照和动态 Previs，再跑通 Finder → Preview → 缩放局部 → 电影化切镜的语义动作。支持任意帧重复求值、替换照片、可编辑本地 HTML 及 MP4 输出。独立 HTML 与视频渲染需分别验证。

macOS 通过后，再用 Windows 验证**换 Skin 而非重写内核**的能力。原生 AE/PR 插件继续保留为后续阶段，不作为首轮验收。
