# XPIN-Desktop｜制作与验收流程（2026-10-16）

这是**适用于本项目的制作流程**，不是要把其他 XPIN 项目的全部规则照搬过来。

## 一、从参考到成片的阶段门槛

### G0｜明确输入和信息重点

读取用户的**截图视觉基准、素材、语义要求、画幅、时长/口播 Marker**。区分已提供与未提供，不虚构素材、模板规格或审核结论。

### G1｜先参考、后创作

- 先研究**成熟 Motion Design/科技广告/系统交互动画案例**与可以复用的源码/资产，再提出符合本项目的视觉方案；有来源则记录出处。
- 优先查看提供素材的**品牌本土官方渠道**，中国产品优先中国大陆官网与中文官方素材；按需要补充付费库、作者出售、视频社区等。
- 提取可迁移的设计语言、动画片段和镜头节奏，避免照搬成一个无关的复制品。
- LottieFiles `motion-design-skill` 等可以作为候选方法参考，不假定 Codex 环境已安装；是否引入以验证结果为准。

### G2｜先 Styleframes，再动态 Previs

- 根据用户截图先做 **macOS 关键帧视觉对照**，识别窗口比例、字体、材质、图标、视觉重心。
- **不仅看静态图**，必须给出涵盖真实时长、鼠标行为、镜头组接的动态 Previs。
- 先确认镜头设计，再写大型组件和真实渲染管线；预演应可快速修改。
- 先解决表达是否容易理解，再追求炫技；能用简单动画表达的，不堆叠三维旋转、粒子和过量玻璃。

### G3｜导演主动设计运动，而非套缓动

Agent 的任务包括**视觉创意、运动编舞、镜头调度、节奏导演和质量判断**，不能只把画面做成机械插值。

- 从**叙事意图和情绪**决定运动性格：精确、轻盈、克制、快速、悬停等。
- 区分 **Primary / Secondary / Ambient**：主体动作引导注意，次级动作解释反馈，环境运动通常从简。
- 设计 **Anticipation → Main Action → Reaction → Resolution**，按需要使用预备动作、跟随与收尾，不强行套固定过冲/弹簧。
- 关注相邻动作间的**速度连续性、因果性和观众注意力转移**；交互瞬间的鼠标、点击反馈与窗口响应保持同步。
- 按语义主动选择 **全景 / 中景 / 特写 / 微距、不同机位、切镜、转场、动静快慢**。不为省事一镜到底，也不为了炫技每秒切镜。
- 口播节点优先，支持镜头、构图和时间点锁定；局部修改应尽量不影响已确认镜头。

### G4｜工程化与可编辑交付

- **复用优先**：先找可靠 UI 素材/开源实现/组件方案，优先做高频、可配置的通用模块。
- UI 必须有真实结构、状态与逻辑操作；图片、文字、尺寸、颜色、动画、镜头位置和时长可修改。
- 图层/组件以**可读、稳定的 ID 与中文属性面板**管理；适合 Agent 和用户接力编辑。
- 在保持可维护性的前提下使用适合镜头的 2D、2.5D 或 3D；不为了技术完整牺牲制作效率。
- 单 HTML 可以直接本地打开预览是**交付目标**；若某能力需本地服务器、Node、Chromium 或 FFmpeg，需明确说明，不得宣称零依赖。
- 视频导出与独立 HTML 导出是两个验收项；后台逐帧渲染不可默认为与浏览器实时播放完全一致。
- 参考场景可输出 MP4 / PNG 序列，未来再评估透明通道、AE/PR 桥接。

### G5｜实际审片并回修

看**真实渲染的视频**，不是仅检查源代码或截图。

检查：**信息一眼可懂、构图、视觉基准相似度、字体可读性、交互因果、鼠标轨迹、缓动与速度衔接、镜头景别、切点、帧精确性、视频色彩**。

发现问题应判断是**设计层**、**动画/状态层**还是**渲染层**，定位后修复；不得仅因代码能运行就宣称镜头完成。

## 二、独立 HTML 与视频的技术验证清单

- [ ] 同一场景逐帧 seek 与反复 seek，UI / 鼠标 / 相机状态一致。
- [ ] 检测视频 FPS、尺寸、时长及镜头切点，抽查关键帧。
- [ ] 图片/字体等资源全部加载后才允许渲染，资源缺失有明确错误提示。
- [ ] 替换图片/文字不需要重写窗口组件或修改镜头核心逻辑。
- [ ] 在干净环境中验证独立 HTML 是否真的可本地运行（含素材打包）。
- [ ] 自动渲染链路的运行前提（Chromium、Playwright、FFmpeg 等）单独列明；不把可行性脚本当成生产级渲染器。
- [ ] Skin 切换测试保留语义和镜头意图；不同系统的布局/操作仍符合各自习惯。
- [ ] 每轮提交附可预览产物、制作说明、已通过/未通过项，未执行的检查明确标注。

## 三、关于既有原型的正确描述

此前有过仓库外的 **macOS/Windows 单 HTML 试验及 Agent JSON / Python 渲染脚本 / MP4 示例**。它对交互外观、时间线和 HTML→视频链路提供了**初步可行性证据**，但尚不等于：

- 已获得用户截图并复刻到指定视觉标准；
- 正式仓库已有可运行的模块化 UI 引擎；
- 不同机器与浏览器环境下已完成离线/字体/布局/视频渲染稳定性验收；
- 原生 AE/PR 插件或无中间文件的视频图层已可用。

现阶段不将外部试验代码直接作为必选工程基础。是否引入实验资产由后续具体开发任务决定。

## 四、对 Codex 的交付原则

提示词与变更说明保持**最小充分上下文**：只写当前目标、必要约束、交付、验收；不要堆砌历史讨论、已否决方案或超出当前目标的其它 Skill 细节。

文档不限制 Codex 探索更高审美或更成熟的技术，但不得改变已确认的视觉基准、行为逻辑、可编辑性和视频输出要求而不说明。始终明确区分**已决策 / 待用户素材 / 待实测 / 已实现**。
