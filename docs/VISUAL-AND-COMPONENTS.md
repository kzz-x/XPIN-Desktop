# 影视化视觉与组件设计 V0.2

**更新：2026-10-16 · 状态：风格原则已确认；macOS 用户截图待提供，具体样式尚未锁定。**

## 视觉参考优先级

**用户提供的现有 macOS 视觉模板截图是首期视觉基准**，而不是 Apple 官网截图，也不是 AE 工程解析数据。先提炼截图的字体、窗口、材质、比例、投影与构图并做同画面对照；在尚未收到截图时，下面的视觉数值仅为方向性建议，不是硬性验收规格。

视觉基准和 Skin / 组件适配规则见 [MACOS-VISUAL-REFERENCE.md](MACOS-VISUAL-REFERENCE.md)。**先验收 macOS，再做其他皮肤**。

## 视觉北极星

**真实系统可辨认 + 影视广告质感 + Motion Design 语言。**

绝不简单叠加玻璃、流光与镜头移动。越是高频的信息操作，越要克制；真正的冲击来自**明确的信息层级、扎实的界面结构、运动的起承转合与有目的的切镜**。

### 建议默认视觉取向

- 系统真实度：**8 / 10**。让观众明确知道正在“操作电脑 / 手机”。
- 影视化自由度：**8 / 10**。允许窗口悬浮、局部特写、相机调度和脱框动画。
- 材质装饰强度：**6 / 10**。可使用玻璃/亚克力/Mica 风格，但内容主体优先。
- 动画表现力：**9 / 10**。交互反馈和镜头组接是核心竞争力。

这些是主观设计标尺，不是引擎的数字约束。

### 参考语言与风格实现

1. **macOS**：保留标题栏、系统按钮、Dock、Finder、Preview 等一眼可识别的结构；可引入通透控制层、柔和阴影。
2. **Windows / Fluent**：保留 Taskbar、Explorer、Photos 的几何层级、圆角、内容结构、Mica / Acrylic 式背景。
3. **空间 UI**：学习空间窗口的间距、纵深、悬浮和摄影调度，但不把传统桌面做成完全不可信的 VR UI。
4. **Motion Graphic**：借鉴微软产品动效等将平面图形材质化的方式，细节通过构图、反射、运动、柔和形变营造，不强迫所有元素 3D 化。
5. **团队视觉**：现有 AE macOS 风格模板可作为未来独立 Skin 的视觉参考；需要先取得可用参考和资产，不能推断其具体设计参数。

## 视觉基础变量（后续做 Token 系统）

每套 Skin 至少应能定义：

| 维度 | 内容 |
| --- | --- |
| Typographic | 字体家族、字号层级、字重、行高、字间距；支持中英混排 |
| Layout | 网格、边距、间距、窗口比例、标题栏高度、按钮尺寸 |
| Shape | 圆角、描边、分割线、浮层层级 |
| Color | 背景、强调色、文字、控件状态、暗/亮模式 |
| Material | 不透明、半透明、Blur、反射强度、粗糙度、投影 |
| Motion | 入出场、悬停、打开、折叠、焦点切换的节奏与弹性 |
| Space | Z 深度、轻微透视、窗口堆叠、视差与焦点策略 |

默认要求 **暗色/亮色可配置，文字高对比且不被景深/反射破坏**。1080p / 9:16 下仍可读，不是仅适配高分辨率截图。

## 三种舞台与转换

### A. Desktop Space

- 真实桌面环境、壁纸、图标布局、Finder/Explorer、Dock/Taskbar。
- 相机建立整体构图，UI 操作不受虚构景深影响。
- 用于识别“正在使用哪一个系统、打开哪一个文件”。

### B. Floating Stage

- 单窗口/多窗口作为电影化拍摄对象。
- 窗口轻度 Z 分层，桌面可弱化或隐藏。
- 支持前后景对焦、视角变化、阴影和相机 Follow。

### C. Graphic Canvas

- 图片/文本/卡片/节点脱离窗口的“系统外壳”。
- 可布局为比较表、节点图、时间线、信息网格。
- 从窗口到卡片转换需维持**内容对象身份和状态**，而非替换为毫无关系的新元素。

## 组件架构

组件不是截图，不只是漂亮外形。必须同时拥有：**内容结构、可视状态、可接受的交互行为、可被镜头定位的语义锚点、系统 Skin**。

| 组件 | 内容与状态 | 动作能力 | 镜头常用目标 |
| --- | --- | --- | --- |
| Desktop | 壁纸、图标、Dock/Taskbar | 选择、拖拽、启动 | 全景、屏幕区块 |
| Window | 标题栏、控制按钮、尺寸、Z 顺序 | 打开、关闭、移动、缩放、切换焦点 | 窗口中心/标题栏 |
| File Browser | 路径、文件树、列表/图标视图、选区 | 浏览、滚动、双击、重命名、拖拽 | 文件行、缩略图 |
| Photo Viewer | 图片、缩放级别、平移偏移 | 打开、放大、滚轮缩放、区域定位 | 图片目标区域 |
| Browser | 地址栏、标签、页面容器 | 打开标签、滚动、定位链接 | 内容区/特定元素 |
| Text Editor | 纯文本/富文本、光标、选择 | 输入、删改、选取、滚动 | 光标/段落 |
| Media Player | 视频帧、时间、播放状态 | 播放、暂停、跳转 | 播放窗口/控件 |
| Info Card | 标题、图、数字、描述 | 出入场、强调、翻转/扩展 | 关键参数 |
| Node Canvas | 节点、连接线、端口、分组 | 拖动、连接、展开、重排 | 重点节点/关系 |
| Menu / Dialog | 层级、内容、激活状态 | 弹出、选取、关闭 | 菜单选项 |

### 应统一提供的组件能力

- **Stable ID**：组件具有稳定身份；Agent 与 Camera 不依赖像素坐标定位。
- **Hit target / Anchor**：如图片中的“芯片区域”、文件缩略图中心、菜单按钮等可引用锚点。
- **State**：文件浏览路径、选中项、窗口焦点、图片 zoom/pan 等逻辑状态。
- **Bounds**：当前帧可计算内容框，供鼠标、相机、自动布局使用。
- **Accessible text**：文字实际可编辑与可检索，而不是全部变成画布截图。
- **Layout rules**：支持窗口尺寸、画幅变化、父子层级与安全区。
- **Export**：该状态在独立 HTML 与离线视频渲染中保持一致。

### 组件设计优先顺序

**首批**：Desktop → Window → File Browser → Photo Viewer → Cursor。它们形成能剪辑的完整演示闭环。

**第二批**：Browser → Text / Media Player → Info Card → Node Canvas。

**第三批**：移动端触控 UI、更多系统 App、复杂概念化界面。

## 组件的影视化强化（可选择，非默认全开）

- **Focus falloff**：聚焦窗口时其他窗口弱化，文字主体保持清楚。
- **Window depth**：轻微 Z 分离和环境投影。
- **Content breakout**：图片/卡片从窗口脱离，保留视觉连续性。
- **Semantic zoom**：放大图片真实区域并重新构图，而不是无脑缩放整个桌面。
- **Lighting sweep**：作为极轻的二级提示，不抢信息焦点。
- **State transition**：同一组件 Native ↔ Cinematic ↔ Creative 的转换。

## 常见反例

- 玻璃过多导致文字看不清，窗口辨识度被装饰覆盖。
- 鼠标点击与组件反馈脱节，双击后出现不相关窗口。
- 用缩放整张屏幕代替真正的窗口操作或内容缩放。
- 动画过长、始终连续推拉，缺少中景和细节切镜。
- 不管 macOS/Windows/iOS 都长得一样，仅更换几个图标。
- 为了“看着高级”让真实的系统操作失去可理解性。
