## 已确认的产品决策

- [x] 项目名 **XPIN-Desktop｜差点桌面**；GitHub：kzz-x/XPIN-Desktop。
- [x] 核心定位：**Agent 原生的 Cinematic UI Motion Engine**。
- [x] **影视化 UI** 为默认视觉方向（原生系统辨识度 + 高质量 Motion Design + 摄影机）。
- [x] macOS / Windows 为首批核心风格，未来扩展 iOS / Android / Node Canvas / 自定义 UI。
- [x] 内容、Skin、组件、行为、摄影机、时间线、渲染分离；Agent 以语义指令编排。
- [x] 操作行为应可信，界面可优化为更适合短视频的视觉效果。
- [x] 镜头设计包含景别组接、主动切镜、口播 Marker、构图/焦点与节奏，不应只是一条相机运动曲线。
- [x] 最终重视**可编辑 HTML / 场景文件**，按需交付 MP4 / 静帧 / 其他后期素材。
- [x] 长期探索 AE/PR 插件，但不把它作为 V0.1 的必要前提。
- [x] 开发先由 Codex 接手，当前仓库优先存文档与计划。

## 实施建议：一次只推进一个可验收阶段

### V0.1｜端到端核心闭环（最高优先）

**目的：证明 Agent 可以生成真实可用的影视 UI 镜头，而不是展示静态假 UI。**

预期内容：
- [ ] 开发工程、启动/本地预览与可编辑场景格式。
- [ ] Desktop / Window / File Browser / Photo Viewer / Cursor 的最小组件组合。
- [ ] macOS / Windows 基础 Skin（可先将 macOS 做精，再验证 Windows 复用）。
- [ ] 打开照片、双击、窗口状态、缩放到图片 Region、鼠标自动指向。
- [ ] 语义动作 → UI 状态 → 摄影机 / 镜头 → Timeline 的链路。
- [ ] 全景 → 中景 / 近景 → 细节的**多镜头**动态 Previs。
- [ ] 时间码 seek、逐帧截图、替换素材、HTML 导出及 MP4 输出。
- [ ] 提供一个用于验收的示例场景与清晰使用说明。

**通过标准（必须全部满足）：**
1. 输入一张产品/主板照片及一句镜头需求，生成至少一段有系统识别度的 UI 操作镜头；
2. 打开照片行为与鼠标点击、窗口响应、图像缩放存在正确时间关系；
3. 至少两种景别，并包含恰当切镜/镜头焦点变化；
4. 在随机抽取的时间点反复 seek，UI/鼠标/相机结果稳定；
5. 能替换图片/标题并直接重新预览；导出独立 HTML 与 MP4；
6. 以 macOS 为主完成视觉审核，再确认 Windows 版本的复用链路。

### V0.2｜可视化工作流 / Agent 可控

- [ ] 预览、组件/素材列表、右侧属性、底部时间线的基础编辑器。
- [ ] 图片/文字替换、窗口移动缩放、简单曲线和动作时点调整。
- [ ] Agent 可通过稳定格式/接口创建、修改、验证场景。
- [ ] 可保存用户调整并被 Agent 无损重读；具备错误诊断。
- [ ] 支持冻结指定镜头的时间/构图，避免后续局部修改牵连其他镜头。

**通过标准：** Agent 与用户可以接力完成同一个镜头，无需重做整个场景。

### V0.3｜图文、网页、节点与形式转换

- [ ] Browser / Text / Media / Info Card / Node Canvas 等组件。
- [ ] 文件窗口、图片、卡片、节点间的形态转换与稳定内容身份。
- [ ] 基础镜头模板及系统→Creative 的跨风格转换。

**通过标准：** 从系统窗口进入节点卡片场景，图片和文字仍可编辑，镜头有逻辑连续性。

### V0.4｜多端风格与输出完善

- [ ] iOS / Android 基础 Skin、触控、移动屏交互。
- [ ] 9:16 重新构图（而非直接裁切）、暗亮风格适配。
- [ ] 视频/图像序列/透明度及稳定性能等按实际需求优化。

**通过标准：** 相同语义意图在桌面与移动端采用合理的不同交互表演。

### V1.0｜后期软件与生产级工作流

- [ ] AE / PR 面板：管理场景、调用外部渲染、同步镜头/时间线信息、替换素材。
- [ ] 渲染缓存、批量任务、错误恢复、项目版本管理。
- [ ] 独立研究宿主内“逐帧渲染 HTML 内容”的原生插件路线，实际验证可行性后再承诺。

**通过标准：** 对源 HTML 作局部修改后，能可靠更新进入剪辑时间线的对应片段，尽量减少人工重复导出和导入。

## 第一轮交给 Codex 的最小任务

1. 先读仓库 AGENTS.md / README.md / docs/PRODUCT.md / docs/DIRECTOR-AND-INTERACTION.md。
2. 不要马上搭建完整 UI 宇宙；先提出“**V0.1 如何最省成本跑通真实一条镜头链路**”的技术方案与风险。
3. 先收集成熟案例 / 开源方案 / 可合法使用的视觉资产，按需要制作关键帧静图或动态 Previs 确认视觉。
4. 在用户确认方案后，完成一个 macOS 图片查看镜头：文件选择 → 双击打开 → 局部放大 → 摄影机特写，支持任意帧 seek 和 HTML / MP4 输出。
5. 再移植同一语义场景到 Windows，验证架构复用；通过后扩展编辑器与组件。

**不要在第一轮就开发 PR/AE 原生插件、复杂三维引擎或完整 OS 行为。**
