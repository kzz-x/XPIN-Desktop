# 行为、镜头导演与时间线 V0.2

**目标：让“一个语义行为”根据系统、视觉模式与场景自动成为可信、具有剪辑节奏的镜头。**

## 核心分层：意图 ≠ 行为 ≠ 表演 ≠ 镜头

以“打开这张图片并放大到芯片”为例：

1. **Intent / 语义**：打开图片、观察芯片区域。
2. **Actions / 行为**：选择文件、双击、启动查看器、缩放、平移。
3. **Performance / 表演**：鼠标路径、等待时长、UI 动效、手势反馈、信息强调。
4. **Camera / 镜头**：全桌面 → 窗口近景 → 芯片细节特写；可切镜。
5. **Timeline / 时间线**：口播 Marker、每个事件的起止、镜头切点、状态与素材。

这种分层使同一意图能映射到 macOS、Windows、iOS 或节点卡片，而无需每次重新写所有动效。

## 语义动作字典（概念性）

### 文件与内容

- openFile / openPhoto / openWebPage
- searchFile / navigateFolder / selectItems
- zoomImageToRegion / compareImages
- typeText / highlightText / scrollToSection
- turnPhotoIntoCard / distributeCards / connectNodes

### 原子交互

| 类型 | 原子动作 |
| --- | --- |
| 鼠标 | 移动、单击、双击、悬停、拖拽、右键、滚轮 |
| 键盘 | 输入、Backspace、快捷键、选择文本 |
| 触摸 | 单击、滑动、长按、双指缩放 |
| 窗口 | 打开、关闭、焦点切换、最大化、缩放、移动 |
| 内容 | 显示、加载完成、局部聚焦、重新布局 |
| 节点 | 创建、删除、移动、端口连接、聚合与展开 |

### 与系统风格之间的映射

“打开照片”可以表现为：

- macOS：Finder 选择文件 → 双击 → Preview。
- Windows：Explorer 选择文件 → 双击 → Photos。
- iOS：Photos 列表 → 轻触照片 → 图片查看界面。
- Node Canvas：图片节点 → 卡片展开 → 聚焦内容。

**操作语义相同，但不要强行保证动作序列完全一致。** 当系统交互习惯不同，应替换行为表演，保留用户要求和镜头意图。

## 目标指向与鼠标系统

- 默认通过**组件 ID、语义 Anchor 和当前布局**寻找目标，不依赖固定屏幕 XY。
- 允许用户显式修正鼠标目标与路径、进入/离开速度、停顿、点击反馈。
- 双击要与文件选中状态及 Preview 出现时点同步。
- 窗口被拖动或分辨率改变后，鼠标与相机仍应跟踪目标。
- 系统默认提供清晰可辨的指针，不必生硬追求每种 OS 的原生像素细节。
- 提供动作序列的多种节奏预设：真实、演示、广告化；默认演示偏影视节奏。

## Camera Director：镜头设计是前期核心

### 常用镜头语法

| 镜头 | 作用 |
| --- | --- |
| Establishing / 全景 | 建立系统与桌面上下文 |
| Window Focus / 中景 | 强调哪个 App / 窗口当前活跃 |
| Detail Push / 近景 | 特定按钮、文件或图片区域 |
| Macro / 微距 | 图片或产品细节与标注 |
| Tracking / 跟随 | 跟随鼠标、窗口或用户注意点 |
| Spatial Reveal / 空间揭示 | 通过视角变化组织多窗口空间 |
| Match Transition / 匹配转场 | UI 中的图像衔接卡片或外部三维镜头 |

### 镜头与节奏规则

1. **按信息切镜，而不是按固定时长切镜。** 语义变化、操作完成、重点转移时才考虑切点。
2. 必须设计**全景 / 中景 / 特写 / 微距**的景别变化，并明确哪些连续运镜、哪些主动切镜。
3. 使用**静态停留 vs 动态推进、慢速建立 vs 快速交互**形成节奏对比。
4. 以口播与字幕 Marker 为时间锚，关键画面应在相应语义节点完成表达。
5. 默认用简单可控的缓动；不要持续漂移、绕转、多余的 3D 运镜。
6. 真正的重点可以用相机、内容缩放、灯光或蒙层强调，但保持主体文字清晰。
7. 编辑时允许**锁定镜头**：锁住关键帧构图、时点或焦点，局部改素材不重排全片。
8. 涉及三维 UI 时先低成本动态 Previs，确认多镜头节奏再增加光影、景深。

### 自动构图

镜头目标应支持：窗口、UI 控件、图片局部区域、文字选区、节点关系、整个桌面。引擎读取目标当前帧边界和留白安全区，推算摄影机和缩放，而不是依赖人工坐标。

### 不同画幅

- 16:9 默认横屏；9:16、1:1、其他比例按独立构图规则处理。
- 不能通过简单裁切把关键信息切掉；必要时重排桌面、窗口、卡片。
- 标注、字幕安全区与鼠标停留位置均需画幅感知。

## 时间线的确定性

- 时间线是**随机可访问**的：任意时间 T 的 UI 状态、鼠标、摄影机、画面可以被独立求值。
- 尽量采用确定性的 timeline evaluator；不能仅靠 requestAnimationFrame 连续播放累积状态。
- 系统应处理加载前后、交叠动作、离散切镜、文本输入、滚动与截图。
- 提供帧率、时长、标记、镜头块、动作块、素材轨道与关键帧。
- 为人工编辑保留可视化轨道和关键属性；语义动作可展开为底层细节进行局部修改。
- 无论前台预览、headless 导出或未来 AE/PR 调用，指定时间的画面结果应一致（允许渲染环境差异的可控容差）。

## 12 秒示例分镜：查看手机主板芯片

| 时间 | 景别 / 镜头 | 动作 | 强调目标 |
| --- | --- | --- | --- |
| 0–1.5s | 全景 | macOS 桌面、Finder 已显示 | 建立场景 |
| 1.5–3s | 中景 | 鼠标移至文件、双击 | 文件 / 指针 |
| 3–4.5s | **切近景** | Preview 窗口打开、获得焦点 | 图片窗口 |
| 4.5–7s | 局部特写 | 缩放图片并重新构图 | 芯片区域 |
| 7–9s | 微距 / 停留 | 圈选芯片、出现型号标注 | 信息识别 |
| 9–11s | 形态匹配转场 | 图片从窗口中脱离成为卡片 | 内容连续性 |
| 11–12s | 中景 / 收束 | 退镜显出节点结构 | 信息组织 |

这是一份**行为与剪辑节奏参考**，不是必须复制的固定 12 秒模板。实际镜头时间要随口播节奏调整。

## Director 模式与 Timeline 模式

**Director Mode**：指定“做什么”、素材、风格、重点与时长；系统自动分解动作并提案镜头。

**Timeline Mode**：细改时点、缓动、指针轨迹、图层、窗口与相机关键帧。两种模式应围绕同一份场景数据，避免切换后数据丢失。

## 质量验收

- 打开、缩放、窗口变化之间存在可理解的因果关系。
- 快进、暂停、向后拖动后 UI/鼠标/镜头状态一致，不发生跳变和残留。
- 内容改变后，语义定位和自动构图可重新计算。
- 切镜服务于信息，不只是为了展示动画技巧。
- 画面在短视频手机屏幕上也能读懂。
